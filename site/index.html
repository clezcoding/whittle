How it works

Read first. Cut second. Undo anytime.

A scan reads and measures and changes nothing. You decide what goes. What goes is moved, not destroyed, until you say otherwise.

  1. 01

    Scan

    Rules and five app sources are read. Nothing is touched. Every item is measured and explained.

  2. 02

    Review

    Each finding says what it is, why it is listed and what happens without it. Only safe items are pre-selected.

  3. 03

    Clean

    Items move to a quarantine at ~/.whittle/quarantine. The journal records every step.

  4. 04

    Undo

    One click, or whittle undo, puts everything back where it was. After the retention time it is freed for good.

Safety is the product

A bug in a rule cannot ruin your day.

A cleaner is only as good as its worst day. Whittle is built in layers, so no single mistake reaches your files.

Read the assurance case

  1. A refusal layer under everything

    Every action passes Safety::check before it touches disk, whatever rule produced it. System paths, your home folder, .git folders, real .app bundles, Keychains, Mail, Photos and iCloud data, and your own never-touch list are refused outright.

  2. Quarantine by default

    Clean moves items to ~/.whittle/quarantine and keeps them for 30 days. Trash and permanent delete are explicit choices, never the default.

  3. An append-only journal

    Every change is recorded in ~/.whittle/journal.jsonl, which is only ever appended to. History and undo are built from it.

  4. The interface only sends ids

    The window never sends a path to delete. It sends ids of findings from the last scan; the Rust backend looks the paths up itself. Even a compromised web view can only act on what a scan found.

  5. No network, by capability

    No telemetry, no account, no update check. The app’s content security policy forbids network requests, so it cannot phone home even by mistake.

  6. A supply chain you can check

    Releases are signed with Sigstore and carry build provenance and an SBOM. Every GitHub Action is pinned to a commit. Fuzzing and property tests cover the safety layer.

        Rules are data
        
A new cache location is one YAML entry.

        
Where Whittle looks lives in rules/*.yaml, not in Rust. Add your own in ~/.config/whittle/rules/ or send a pull request.

      

      
    
        
  • Declarative. Paths, exclusions, minimum age and size, risk, platform.
    • 
        
  • Gated. A rule only produces findings. The safety layer still decides.
    • 
        
  • Explained. The note is what you read in the drawer.
    • 
        
  • The easiest contribution. One entry, one pull request, no toolchain needed.
    • 
      

    

    

      
rules/caches.yaml


- id: xcode-derived-data
  name: Xcode DerivedData
  category: dev
  risk: safe
  regenerable: true
  note: Build products and indexes. Xcode rebuilds them.
  paths: ["~/Library/Developer/Xcode/DerivedData/*"]
  exclude: ["ModuleCache.noindex"]
  min_age_days: 7
  platform: macos

    

  







  

    

      Install
      
Pick your way in.

      
A universal build for Apple silicon and Intel, macOS 11 or later.

    

    

      

        
        
        
        
      


      

        
Recommended. The cask installs the app and removes the macOS quarantine flag for you. The formula installs only the command line.

        
# the app
brew tap clezcoding/tap
brew install --cask clezcoding/tap/whittle

# or the command line only
brew install --formula clezcoding/tap/whittle

      


      

        
Download the universal .dmg from the latest release and drag Whittle to Applications.

        Latest release
        
First launch. Until the app is notarized with an Apple Developer ID, macOS shows “Whittle can’t be opened”. That is Gatekeeper, not a bug. Right-click the app, choose Open, then Open again, or run once:
          
xattr -dr com.apple.quarantine /Applications/Whittle.app

      


      

        
You need the Xcode command line tools, Rust, Node 20+ and pnpm.

        
git clone https://github.com/clezcoding/whittle
cd whittle
./scripts/install-mac.sh

      


      

        
Every release file is signed with Sigstore, keyless, from the release workflow, and has a build-provenance attestation. There is no long-lived private key to steal.

        
# the checksum list is signed; check your download against it
cosign verify-blob \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/clezcoding/whittle/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing

# who built it, from which commit
gh attestation verify Whittle_0.1.0_universal.dmg --repo clezcoding/whittle

      FAQ
      
Questions people ask first.

    

    

      
Will it delete my files?
Not unless you choose that. Clean moves items to a quarantine and keeps them for 30 days by default. You can undo from the app or with whittle undo. Trash and permanent delete are separate, explicit choices.

      
Does it talk to the internet?
No. No telemetry, no account, no update check. The app has no permission to make network requests and its content security policy forbids them. You can check this in the source, or with a firewall.

      
Why does macOS say it cannot be opened?
The app is not yet notarized with an Apple Developer ID, so Gatekeeper warns on first launch. Right-click, choose Open, or use the Homebrew cask, which clears the flag. The signatures on each release let you verify the download independently. Notarized releases are on the roadmap.

      
How does it know an app is really gone?
Installed apps are read from five sources, not just /Applications. Leftovers always come with a confidence and are rated review, never pre-selected.

      
Can I protect a folder?
Yes. Add it to the never-touch list in Settings, or run whittle ignore <path>. The list is shared between the app and the command line, and the safety layer enforces it for every rule.

      
Can I add my own locations?
Write a YAML rule in ~/.config/whittle/rules/. It appears in the Rules view straight away. If it would help others, send it as a pull request.

      
Which macOS versions work?
macOS 11 or later, on Apple silicon and Intel, from one universal build.

      
Is it free?
Yes. Whittle is open source under MIT or Apache-2.0, your choice.
